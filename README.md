# Daylight — personal hub prototype

Deployment: see [DEPLOYMENT.md](DEPLOYMENT.md). For remote Hue controls on Render, follow [HUE-DEPLOYMENT.md](HUE-DEPLOYMENT.md). The notes below describe the original prototype; the current app also includes Supabase authentication/storage and weekly scheduling.

Run `npm install`, then `npm run dev`. Open the localhost address Vite prints. `npm run build` checks TypeScript and creates production assets; `npm test` verifies core scheduling constraints.

Supabase setup: copy `.env.example` to `.env.local` (the project URL is already present) and put the project's `sb_publishable_...` key in `VITE_SUPABASE_PUBLISHABLE_KEY`. Never put a Supabase secret or service-role key in a `VITE_` variable or browser code. Cloud data access is not active yet; apply the migration in `supabase/migrations` after confirming the project schema, then wire auth and data repositories.

The prototype supports task selection (buttons or desktop drag/drop), task types and projects, due dates, estimates, hub-only priorities, and a Done toggle that mirrors the checkbox in the Notion database. Its task table follows the Notion fields: Task, Type, Project, Due Date, Estimate, Done. The proposed Notion mapping is Task → title, Done → completion, Due Date → deadline, Type → category, Project → project. Created time is source metadata; Days is informational and excluded from scheduling. Add an Estimate (minutes) number property in Notion for task duration; priority remains hub-owned. The prototype also supports three schedule proposals, overload explanations, accepting a plan, replanning, a touch-friendly dashboard, an Activity calendar, a live clock with in-app alarms, and a manual sleep log with monthly history. The dashboard's gym check-in logs one visit per day; completed tasks are recorded on their completion date.

Tasks, the accepted plan, activity history, alarms, and sleep logs are stored in this browser's localStorage. This is a single-day prototype: its plan is not yet date-scoped, and sample calendar events recur on screen as examples. In-app alarms require the browser tab and Windows to remain awake; sleeping or shutting down can prevent them from ringing. For a reliable alarm while Windows sleeps, use a dedicated alarm device or the Windows Clock app after checking its behavior on this Surface. No Google Calendar connection, AI, cloud database, cross-device sync, full offline PWA support, block dragging/pinning, or automatic idle timer is implemented yet. Notion is no longer part of the planned data flow. Do not use it as your authoritative calendar. Sample tasks are labeled as such; newly created tasks are local.

Next milestone: date-scoped tasks/plans and manual block adjustments, followed by authenticated storage and server-side read-only Google Calendar/Notion integrations. The scheduling algorithm is deterministic; Focus prefers longer work at equal priority, Balanced prefers shorter work with longer breaks, and Essentials defers optional tasks below high priority. Whole tasks only; splitting and task dependencies follow later.
